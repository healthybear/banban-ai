# 产品路线图

## 版本规划概览

```
MVP (v0.1)          v1.0              v2.0              v3.0
   |                 |                 |                 |

   |                 |                 |                 |
```

## Phase 0: MVP (v0.1) - 3个月

**目标**: 验证核心概念，打造围绕"食"的贴身管家，获得种子用户反馈

**定位**: 一个会记录你吃喝、帮你做决策的智能助手

### 核心功能

#### 1. 美食管家（核心场景）
- [ ] 美食打分与记录
  - 快速打分（1-5 星 + 评价）
  - 拍照记录
  - 自动记录时间和位置
  - 餐厅名称管理
  - 标签系统（菜系、价位、场景）

- [ ] 智能推荐
  - "不知道吃什么"对话入口
  - 基于历史偏好推荐
  - 附近餐厅筛选
  - 避免重复逻辑
  - 推荐理由说明

- [ ] 位置记录
  - 自动获取位置
  - 地图选点
  - 位置历史查看
  - 隐私设置

#### 2. 基础对话能力
- [ ] 自然语言交互
  - 接入 Claude/DeepSeek
  - 美食相关意图识别
  - 上下文管理

- [ ] 对话式打分
  - "刚吃的火锅不错，8分"
  - "上次在哪吃的日料？"
  - "推荐个附近的川菜"

#### 3. LLM 适配层
- [ ] 多模型支持
  - 支持 2-3 个模型
  - 自动额度检测
  - 模型切换

#### 4. Web 界面
- [ ] 聊天界面
  - 基础对话
  - 快速打分卡片
  - 推荐结果展示

- [ ] 美食记录管理
  - 历史记录列表
  - 地图可视化
  - 筛选和搜索

### 技术债务
- 暂不考虑性能优化
- 单机部署即可
- MongoDB 单实例

### 交付物
- 可运行的 Demo
- 美食打分与推荐功能完整可用
- 基础文档
- 10 个种子用户（爱吃的朋友）

### 里程碑
- Week 4: 后端框架 + LLM 适配层完成
- Week 8: 美食打分与推荐功能完成
- Week 10: Web 界面完成
- Week 12: MVP 上线，开始邀请种子用户

### 成功指标
- [ ] 种子用户日均打分 > 1 次
- [ ] 推荐准确率 > 70%（用户反馈）
- [ ] 用户留存率 > 50%（7 天）

详见：[衣食住行生活场景功能规划](../01-requirements/features/life-scenarios.md)

## 技术演进路线

### 架构演进
```
MVP: 单体应用
 ↓
v1.0: 模块化单体
 ↓
v2.0: 微服务架构
 ↓
v3.0: 云原生架构
```

### 数据库演进
```
MVP: SQLite/内存
 ↓
v1.0: PostgreSQL + Redis + Qdrant
 ↓
v2.0: 分库分表 + 缓存集群
 ↓
v3.0: 分布式数据库
```

### 部署演进
```
MVP: 单机部署
 ↓
v1.0: Docker部署
 ↓
v2.0: Kubernetes集群
 ↓
v3.0: 多云部署
```

## 资源规划

### 团队规模
- MVP: 2-3人（全栈）
- v1.0: 5-6人（前端2 + 后端2 + 产品1 + 测试1）
- v2.0: 10-12人（增加移动端、运维）
- v3.0: 20+人（增加销售、客服、企业服务）

### 预算估算
- MVP: 基础服务器 + API费用，约 ¥5,000/月
- v1.0: 云服务 + API费用，约 ¥20,000/月
- v2.0: 扩展服务器 + 带宽，约 ¥50,000/月
- v3.0: 企业级基础设施，约 ¥200,000/月

## 风险与应对

### 技术风险
| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| Multi-Agent协调复杂度高 | 高 | 中 | 分阶段实现，先单Agent后多Agent |
| 多模型切换一致性问题 | 中 | 高 | 建立完善的测试用例 |
| 插件安全性问题 | 高 | 中 | 沙箱隔离 + 权限控制 |
| 性能瓶颈 | 中 | 中 | 提前做性能测试和优化 |

### 市场风险
| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| 大厂推出竞品 | 高 | 高 | 聚焦差异化，快速迭代 |
| 用户增长缓慢 | 中 | 中 | 加强运营和推广 |
| 插件生态建设困难 | 中 | 中 | 开发者激励计划 |
