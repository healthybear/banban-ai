# 需求规划与优先级

## 文档目的

本文档整理了智能助手平台的所有需求，并按优先级和版本进行规划。

---

## 需求分类

### 按优先级分类
- **P0**: MVP必须，核心功能
- **P1**: v1.0重要功能
- **P2**: v2.0及以后
- **P3**: 可选功能，视情况而定

### 按模块分类
- **核心能力**: LLM适配、Agent系统、个性化
- **功能模块**: 日程、任务、笔记等
- **平台接入**: Web、移动端、插件
- **基础设施**: 数据库、监控、部署

---

## MVP (v0.1) 需求清单 - 3个月

### 目标
验证核心概念，获得种子用户反馈，完成基础功能闭环。

### 核心需求

#### 1. LLM适配层 (P0)
**需求描述**:
- 支持多个大模型提供商（Claude, DeepSeek, Kimi, 豆包）
- 自动检测各模型的免费额度
- 智能切换：优先使用有免费额度的模型
- 支持手动指定模型
- 统一的接口抽象

**验收标准**:
- [ ] 至少接入2个LLM提供商
- [ ] 能够自动检测额度并切换
- [ ] 切换模型时对话上下文不丢失
- [ ] API响应时间 < 3秒

**技术实现**:
- Node.js + NestJS
- 适配器模式
- 本地额度计数器

---

#### 2. 基础对话能力 (P0)
**需求描述**:
- 支持文本对话
- 上下文管理（至少保留最近10轮对话）
- 基础的意图识别
- 流式响应（打字机效果）

**验收标准**:
- [ ] 能够进行多轮对话
- [ ] 上下文理解准确
- [ ] 支持流式输出
- [ ] 响应自然流畅

**技术实现**:
- WebSocket实时通信
- 对话历史存储（Redis）
- SSE流式响应

---

#### 3. 日程管理 (P0)
**需求描述**:
- 日程的增删改查
- 时间冲突检测
- 简单的提醒功能
- 通过对话创建日程

**用户故事**:
- 作为用户，我想说"明天下午3点开会"，系统自动创建日程
- 作为用户，我想查看今天的日程安排
- 作为用户，我想修改或删除日程
- 作为用户，我想在日程冲突时收到提醒

**验收标准**:
- [ ] 支持自然语言创建日程
- [ ] 能够检测时间冲突
- [ ] 日程列表展示清晰
- [ ] 提醒功能正常

**技术实现**:
- PostgreSQL存储日程数据
- NLP解析时间表达
- 定时任务提醒

---

#### 4. Web界面 (P0)
**需求描述**:
- 聊天界面
- 日程展示界面
- 基础设置页面
- 响应式设计

**界面要求**:
- 简洁美观
- 操作流畅
- 移动端适配

**验收标准**:
- [ ] 聊天界面支持文本输入和展示
- [ ] 日程以日历或列表形式展示
- [ ] 设置页面可以切换模型
- [ ] 在手机浏览器上可用

**技术实现**:
- Vue 3 + Vite
- Naive UI / Element Plus
- 响应式布局

---

### 非功能需求

#### 性能要求
- 页面加载时间 < 2秒
- API响应时间 < 3秒
- 支持10个并发用户

#### 安全要求
- 用户认证（简单的账号密码）
- HTTPS加密
- 基础的输入验证

#### 可用性要求
- 系统可用性 > 95%
- 数据备份机制

---

### MVP不包括的功能
- ❌ Multi-Agent协作
- ❌ 个性化引擎
- ❌ 插件系统
- ❌ 移动端App
- ❌ 语音对话
- ❌ 浏览器插件
- ❌ IDE插件

---

## v1.0 需求清单 - 3个月

### 目标
打造完整的Multi-Agent平台，支持基础个性化和插件系统。

### 核心需求

#### 1. Multi-Agent系统 (P1)
**需求描述**:
- Agent编排引擎
- 支持多个专业Agent协作
- 可视化工作流编辑器
- 工作流保存和分享

**专业Agent列表**:
- 日程管理Agent
- 任务规划Agent
- 信息检索Agent
- 第三方集成Agent

**验收标准**:
- [ ] 能够定义和执行工作流
- [ ] 多个Agent能够协作完成任务
- [ ] 可视化编辑器易用
- [ ] 工作流可以保存和复用

**技术实现**:
- 自研Agent编排引擎或基于LangGraph
- Vue Flow可视化编辑
- 工作流存储（PostgreSQL）

---

#### 2. 个性化引擎 (P1)
**需求描述**:
- 角色人设管理
- 长期记忆系统
- 基础RAG支持
- 酒馆API集成

**功能详情**:
- **人设管理**: 定义性格、说话风格、背景
- **长期记忆**: 记住用户偏好、习惯、重要信息
- **RAG**: 导入个人知识库，检索相关信息
- **酒馆API**: 增强角色扮演能力

**验收标准**:
- [ ] 可以创建和管理角色人设
- [ ] 对话中能体现人设特征
- [ ] 能够记住用户的重要信息
- [ ] RAG检索准确率 > 80%

**技术实现**:
- Qdrant向量数据库
- Embedding模型
- 酒馆API集成

---

#### 3. 插件系统 (P1)
**需求描述**:
- 插件框架（远程+本地混合）
- 插件市场
- 核心插件开发
- 插件开发文档

**核心插件**:
- Google Calendar同步
- Notion集成
- Todoist集成
- 天气查询
- 邮件集成

**验收标准**:
- [ ] 插件接口标准化
- [ ] 至少5个核心插件可用
- [ ] 插件市场可以浏览和安装
- [ ] 插件开发文档完善

**技术实现**:
- 远程插件：HTTP API调用
- 本地插件：动态加载 + 沙箱隔离
- 插件市场：Web界面

---

#### 4. 动态扩展能力 (P1)

##### Web端
**需求描述**:
- 动态加载Vue组件
- WASM模块支持
- 热更新机制

**验收标准**:
- [ ] 可以动态加载新功能
- [ ] WASM模块正常工作
- [ ] 热更新不需要刷新页面

**技术实现**:
- 动态import
- Kotlin -> WASM编译
- WebSocket推送更新

##### 后端
**需求描述**:
- 插件热加载
- 远程插件调用
- 插件版本管理

**验收标准**:
- [ ] 插件可以热加载
- [ ] 远程插件调用稳定
- [ ] 支持插件版本回滚

---

#### 5. 数据采集 (P1)
**需求描述**:
- 对话数据收集
- 用户行为追踪
- 数据脱敏
- 导出训练数据

**隐私保护**:
- 用户同意机制
- 数据脱敏选项
- 数据删除功能

**验收标准**:
- [ ] 数据收集完整
- [ ] 隐私保护到位
- [ ] 可以导出标准格式

---

## v2.0 需求清单 - 6个月

### 目标
建立插件生态，增强个性化能力，扩大用户规模。

### 核心需求

#### 1. 移动端App (P2)
**需求描述**:
- Flutter跨平台开发
- Android深度定制（Kotlin + Compose）
- 小程序引擎
- 热更新支持

**功能要求**:
- 完整的聊天功能
- 日程管理
- 推送通知
- 语音输入
- 离线支持

**动态扩展**:
- 小程序方式加载新功能
- 热更新业务逻辑
- Android优先，iOS谨慎

**验收标准**:
- [ ] iOS和Android App上线
- [ ] 功能与Web端一致
- [ ] 小程序引擎可用
- [ ] 热更新机制稳定

**技术实现**:
- Flutter + Dart
- Kotlin + Compose (Android)
- 小程序引擎（自研或开源）
- CodePush式热更新

---

#### 2. 语音交互 (P2)
**需求描述**:
- 语音输入（STT）
- 语音输出（TTS）
- 连续对话
- 语音唤醒

**验收标准**:
- [ ] 语音识别准确率 > 90%
- [ ] 语音合成自然流畅
- [ ] 支持连续对话
- [ ] 多语言支持

**技术实现**:
- STT: Whisper API / 讯飞
- TTS: OpenAI TTS / Azure Speech
- 唤醒词检测

---

#### 3. IDE集成 (P2)
**需求描述**:
- VS Code插件
- JetBrains插件
- 代码助手功能
- 文档查询

**验收标准**:
- [ ] VS Code插件发布
- [ ] JetBrains插件发布
- [ ] 代码补全准确
- [ ] 文档查询快速

---

#### 4. 浏览器插件 (P2)
**需求描述**:
- Chrome Extension
- Edge Extension
- 快捷唤起
- 网页内容集成

**验收标准**:
- [ ] 插件上架商店
- [ ] 快捷键唤起
- [ ] 可以总结网页内容

---

#### 5. 高级个性化 (P2)
**需求描述**:
- 用户画像
- 习惯学习
- 主动推荐
- 情感模拟

**验收标准**:
- [ ] 能够分析用户习惯
- [ ] 主动推荐准确
- [ ] 情感表达自然

## 技术债务管理

### MVP阶段可接受的技术债务
- 简单的用户认证（不做OAuth）
- 单机部署（不做分布式）
- 简单的错误处理
- 最小化的测试覆盖

### v1.0必须偿还的技术债务
- 完善的用户认证和授权
- 完整的错误处理和日志
- 单元测试覆盖率 > 60%
- API文档完善

### v2.0必须偿还的技术债务
- 分布式部署
- 完整的监控和告警
- 性能优化
- 安全加固

## 风险与依赖

### 关键依赖
| 依赖项 | 影响范围 | 风险等级 | 应对措施 |
|--------|----------|----------|----------|
| LLM API可用性 | 核心功能 | 高 | 多模型备份 |
| 向量数据库 | 个性化 | 中 | 自建Qdrant |
| 小程序引擎 | 移动端扩展 | 中 | 开源方案备选 |

### 技术风险
| 风险 | 影响 | 概率 | 应对 |
|------|------|------|------|
| Multi-Agent协调复杂 | 高 | 中 | 分阶段实现 |
| WASM兼容性 | 中 | 低 | JS降级方案 |
| 小程序引擎开发难度 | 高 | 中 | 参考开源方案 |
| Flutter热更新iOS限制 | 中 | 高 | Android先行 |
