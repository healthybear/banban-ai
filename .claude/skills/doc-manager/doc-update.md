# 文档更新 Skill

更新大文档的特定部分，避免重写整个文档，节省token。

## 使用方法

```
/doc-update [文档] [章节] [更新内容描述]
```

## 示例

```bash
# 更新产品愿景的目标用户章节
/doc-update vision 目标用户 添加企业用户画像

# 更新需求规划的MVP范围
/doc-update requirements-planning MVP 添加WebSocket实时通信需求

# 更新技术选型文档
/doc-update tech-stack-update 数据库 添加MongoDB作为备选方案
```

## 实现流程

当用户调用此skill时，执行以下步骤：

### 第一步：定位章节
```
1. 找到目标文档
2. 定位要更新的章节
3. 读取该章节的当前内容
4. 显示给用户确认
```

### 第二步：生成更新
```
1. 根据用户描述生成新内容
2. 保持原有格式和风格
3. 显示新旧对比
4. 询问用户确认
```

### 第三步：应用更新
```
1. 使用Edit工具替换章节内容
2. 保持其他部分不变
3. 更新文档的updated字段
4. 提交更改
```

## 支持的更新类型

### 1. 添加内容
```bash
/doc-update vision 目标用户 添加企业用户画像

# 在现有内容后添加新内容
```

### 2. 修改内容
```bash
/doc-update roadmap MVP 将时间从3个月改为6个月

# 修改特定内容
```

### 3. 删除内容
```bash
/doc-update requirements-planning Backlog 删除已取消的功能

# 删除指定内容
```

### 4. 重组内容
```bash
/doc-update tech-stack 前端技术栈 重新组织章节结构

# 重新组织章节
```

## 智能特性

### 1. 保持一致性
- 自动匹配原文档的格式
- 保持标题层级
- 保持列表样式
- 保持代码块格式

### 2. 上下文感知
- 理解章节的上下文
- 保持逻辑连贯
- 避免重复内容

### 3. 版本追踪
- 自动更新updated字段
- 可选：创建备份
- 可选：记录到CHANGELOG

## 优势

- ✅ 只修改需要的部分
- ✅ 大幅节省token
- ✅ 保持文档一致性
- ✅ 支持批量更新
- ✅ 可以撤销更改

## 高级用法

### 批量更新
```bash
# 更新多个章节
/doc-update vision "目标用户,成功指标" 根据最新市场调研更新

# 更新多个文档
/doc-update "vision,roadmap" MVP 调整MVP范围
```

### 条件更新
```bash
# 只在满足条件时更新
/doc-update requirements-planning MVP 如果时间超过3个月则调整为6个月
```

### 模板更新
```bash
# 使用模板更新
/doc-update PRD-llm-adapter 接口设计 使用API模板添加接口文档
```
